# Narrata

**Краткий анализ таблиц и текстовых отчётов с помощью ИИ.**

Загрузите CSV, Excel или вставьте текст — получите основной вывод, интерактивные графики и ответы на вопросы по данным. Регистрация не требуется.

[Открыть сервис](https://narrata-nine.vercel.app/)

[Как запустить](#как-запустить-локально) · [Какой стек используется](#стек)

## Возможности

- Загрузка CSV, XLSX и XLS через drag-and-drop или выбор файла; вставка текста.
- Основной вывод и 2–3 предложения с объяснением и контекстом источника.
- Интерактивные графики: модель выбирает представления, код рассчитывает табличные значения.
- Вопросы по источнику: поиск, сравнения, группировки, суммы и доли.
- Экспорт выводов, графиков и истории чата в PDF после завершения анализа.
- Индикатор загрузки, понятные сообщения об ошибках и повтор анализа.

Если запрошенных сведений нет в источнике, сервис отвечает: **«В этом отчете нет такой информации»**.

## Как запустить локально

Инструкция ниже рассчитана на запуск на своём компьютере и подключение через GigaChat API в кабинете Studio. Отдельную базу данных устанавливать не нужно.

### 1. Установите Node.js и Git

Установите [Node.js](https://nodejs.org/en/download) версии 22 или новее и [Git](https://git-scm.com/downloads). npm устанавливается вместе с Node.js. После установки откройте новый терминал: PowerShell в Windows или Terminal в macOS/Linux.

Проверьте, что программы доступны:

```bash
node --version
npm --version
git --version
```

Все три команды должны вывести номер версии. Если команда не найдена, проверьте установку и заново откройте терминал.

### 2. Получите доступ к GigaChat API

1. Откройте [личный кабинет Studio](https://developers.sber.ru/studio/workspaces/my-space/get/gigachat-api) и войдите через Сбер ID.
2. Нажмите **«Создать проект»**, выберите **GigaChat API** в разделе **«AI-модели»**, задайте название и примите условия использования.
3. В созданном проекте откройте **«Настройки API»** и нажмите **«Получить ключ»**.
4. Скопируйте **Authorization Key** и сохраните его: он отображается только один раз. Для Narrata нужен именно этот ключ, а не отдельные Client ID или Client Secret. Ключ может получить владелец или администратор проекта.
5. Найдите значение **Scope** в настройках проекта. Для физического лица это `GIGACHAT_API_PERS`.

Подробности: [создание проекта](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-create-project) и [получение ключа](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api).

Проверьте в кабинете доступность модели и остаток токенов — это лимит использования API. Условия бесплатного доступа и оплаты описаны в [тарифах GigaChat](https://developers.sber.ru/docs/ru/gigachat/tariffs/individual-tariffs). С 1 сентября 2026 года новые клиенты или клиенты без прежних покупок оплачивают работу с моделями через Cloud.ru. Эта инструкция описывает подключение с Authorization Key из Studio; интеграция с Cloud.ru в проекте не реализована.

Доступ к обычному чату на giga.chat не заменяет доступ к API. Временный **Access token** вручную получать не нужно: Narrata получает и обновляет его по Authorization Key.

### 3. Скачайте проект и установите зависимости

В терминале перейдите в папку, где хотите разместить проект, и выполните:

```bash
git clone https://github.com/na-mramornom-nizu/narrata.git
cd narrata
npm ci
```

`git clone` скачивает код, `cd narrata` открывает папку проекта, а `npm ci` устанавливает библиотеки из зафиксированного списка зависимостей. Дождитесь окончания установки. Все следующие команды выполняйте внутри папки `narrata`.

### 4. Настройте подключение к модели

Создайте `.env.local` — локальный файл настроек — на основе готового примера.

**Windows, PowerShell:**

```powershell
Copy-Item .env.example .env.local
notepad .env.local
```

**macOS/Linux:**

```bash
cp .env.example .env.local
```

Откройте созданный файл в текстовом редакторе, замените пустое значение ключа и сохраните файл:

```dotenv
GIGACHAT_AUTH_KEY=ваш_ключ_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
```

| Переменная | Что указать |
| --- | --- |
| `GIGACHAT_AUTH_KEY` | Полное значение Authorization Key из Studio. Вставьте его после `=`, без префиксов `Basic` или `Bearer`. |
| `GIGACHAT_SCOPE` | Значение Scope вашего проекта. Для физлиц — `GIGACHAT_API_PERS`; для ИП/юрлиц оно может быть `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. |
| `GIGACHAT_MODEL` | ID доступной модели. В примере — `GigaChat`; при другой модели укажите её ID из кабинета/API. |
| `GIGACHAT_API_URL` | Необязательный полный адрес генерации ответов. По умолчанию используется прежнее подключение, указанное ниже. |

Scope должен соответствовать вашему доступу: [описание вариантов авторизации](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

**Адрес API зависит от подключения.** По умолчанию Narrata использует `https://gigachat.devices.sberbank.ru/api/v1/chat/completions` — адрес работающего проекта. По документации провайдера он доступен для подключений, оформленных до 17 июля 2026 года. Для нового подключения используется домен `api.giga.chat`; укажите полный адрес в `.env.local`:

```dotenv
GIGACHAT_API_URL=https://api.giga.chat/api/v1/chat/completions
```

Этот путь указан в примерах [официального SDK](https://developers.sber.ru/docs/ru/gigachat/quickstart/ind-using-api). Если провайдер выдал другой адрес генерации ответов, используйте его. Не меняйте код для выбора адреса; после изменения переменной перезапустите приложение.

Файл `.env.local` должен лежать рядом с `package.json`, а не внутри `app`. В Windows проверьте, что Блокнот не добавил расширение `.txt`. Ключ используется только в обработчиках API; файл исключён из Git. Не добавляйте ключ в README или переменные с префиксом `NEXT_PUBLIC_`.

Сертификат для подключения к GigaChat уже включён в проект и используется клиентом Node.js. Для запуска Narrata вручную устанавливать его в Windows не требуется. Проверка HTTPS включена.

### 5. Запустите приложение

```bash
npm run dev
```

Оставьте терминал открытым. Когда появится сообщение о готовности, откройте [http://localhost:3000](http://localhost:3000) в браузере. Если порт 3000 занят, используйте адрес, напечатанный в терминале, или задайте порт явно:

```bash
npm run dev -- --port 3001
```

В таком случае адрес — [http://localhost:3001](http://localhost:3001). Чтобы остановить приложение, нажмите **Ctrl+C** в терминале. После изменения `.env.local` остановите приложение и запустите его заново.

### Если запуск не удался

| Ситуация | Что проверить |
| --- | --- |
| `node`, `npm` или `git` не найдены | Установлены ли Node.js и Git; откройте новый терминал после установки. |
| PowerShell запрещает запуск `npm.ps1` | Используйте `npm.cmd ci` и `npm.cmd run dev` вместо команд `npm`; менять политику выполнения не требуется. |
| Ошибка установки библиотек | Выполняется ли `npm ci` в папке с `package.json` и `package-lock.json`; есть ли интернет и место на диске. |
| Страница открывается, но ИИ недоступен | Сохранён ли ключ в `.env.local`, совпадает ли Scope с кабинетом и перезапущено ли приложение. |
| Ошибка авторизации GigaChat | Используется ли полный Authorization Key, действует ли он и выбран ли правильный Scope. Для нового подключения также проверьте `GIGACHAT_API_URL` по инструкции выше. |
| Запросы к модели отклоняются | Доступна ли указанная модель и остались ли токены/квота в кабинете. |

## Стек

| Задача | Инструменты |
| --- | --- |
| Приложение и API | Next.js 15, React 18, TypeScript |
| Интерфейс | Tailwind CSS, Framer Motion, Lucide |
| Графики | Recharts |
| Чтение CSV и Excel | PapaParse, SheetJS |
| Языковая модель | GigaChat через официальный REST API |
| Расчёты | TypeScript, SQLite через sql.js |
| PDF | pdfmake |
| Хостинг | Vercel |

Next.js объединяет интерфейс и обработчики анализа и чата в одном проекте. Модель помогает интерпретировать данные, а табличные расчёты выполняет код приложения. Отдельная база данных не нужна.

## Пример для проверки

Откройте вкладку **«Вставить текст»** и вставьте учебный отчёт:

```text
Недельный отчёт команды разработки проекта «Аврора».
Из 50 задач 20 находятся на ревью, 10 в работе и 20 завершены.
На ревью приходится 40% задач.
В понедельник завершили 4 задачи, во вторник 6, в среду 10.
```

После анализа задайте вопрос: «В какой день завершили больше всего задач?» По тексту ответ — в среду, 10 задач. На вопрос «Какой бюджет проекта?» сведений в отчёте нет.

## Как устроено приложение

1. **Ввод.** Браузер разбирает файл, проверяет формат и размер, подготавливает колонки и строки. Вставленный текст сохраняется как исходный текст отчёта.
2. **Анализ — `/api/analyze`.** Код рассчитывает факты и варианты графиков по таблице. GigaChat определяет контекст и выбирает визуализации. Факты для нарратива охватывают все группы выбранной разбивки, включая не показанные на графике. Для подтверждённой концентрации суммарного показателя код связывает заголовок с рассчитанными долями; в остальных случаях текст пишет модель, затем выполняются проверки.
3. **Вопросы — `/api/chat`.** Модель предлагает план поиска или расчёта. Приложение проверяет поля и операции, затем выполняет расчёт на TypeScript или SQLite. SQLite работает в памяти отдельного потока с ограничениями ресурсов; разрешено только чтение данных.
4. **Текстовые отчёты.** Модель выбирает факты из исходных фрагментов. Проверяются ссылки на числа для графиков и подтверждающие цитаты для ответов чата.
5. **Экспорт.** PDF создаётся в браузере из текущего анализа и переписки.

Обработка анализа и чата выполняется двумя функциями Next.js на Vercel. Постоянная база отчётов и векторный индекс не используются. Данные передаются обработчикам приложения, а контекст запросов — GigaChat.

Код работы с моделью разделён по ответственности:

- `lib/ai.ts` — входные функции анализа и чата, выбор обработчика для таблицы или текста.
- `lib/ai/` — отдельные сценарии анализа, чата, подготовки ответов и проверки нарратива.
- `lib/prompts/` — инструкции для модели, схемы планов вычислений и инструкции повторных попыток. Промпты сгруппированы по задачам.
- `lib/gigachat.ts` — HTTP-клиент GigaChat: авторизация, токен доступа и запросы к API.

Расчёты и проверка данных находятся в отдельных модулях `lib/`; изменение формулировок промптов не требует менять код расчётов.

## Проверки и сборка

```bash
npm test                 # Автоматические тесты без запросов к модели
npm run typecheck        # Проверка TypeScript
npm run build            # Сборка приложения
npm start                # Запуск собранного приложения
```

Тесты проверяют разбор файлов, расчёты и процентные сравнения, ограничения SQL, текстовые факты, контекст нарратива и PDF. Для проверки качества ответов модели дополнительно используйте свой файл или учебный текст выше.

## Ограничения

| Ограничение | Значение |
| --- | --- |
| Форматы | CSV, XLSX, XLS и вставленный текст; в Excel читается только первый лист. |
| Размер файла | До 20 МиБ (20 971 520 байт). |
| Размер запроса | До 4 000 000 байт: данные после преобразования в JSON вместе с историей чата. Файл меньше 20 МиБ тоже может превысить этот лимит. |
| Вставленный текст | До 50 000 символов. |
| SQL-расчёт | До 8 секунд; выдача ограничена 100 строками. Суммы и количества рассчитываются до сокращения выдачи. |
| Графики | При недостатке числовых фактов графиков может быть меньше двух или не быть вовсе. |

Приложение не сохраняет отчёты между сессиями. Для сохранения результата используйте опцию "Сохранить результат в PDF". 

## Деплой на Vercel

1. Импортируйте GitHub-репозиторий как проект Next.js.
2. Добавьте `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE` и `GIGACHAT_MODEL` в настройки переменных окружения.
3. Выполните деплой. После изменения переменных окружения запустите новый деплой.

Если вашему подключению нужен другой адрес API, добавьте также `GIGACHAT_API_URL` по инструкции локального запуска.

Текущий сайт связан с веткой `main`. `next.config.js` включает SQLite и CA-сертификат в сборку функций. Происхождение сертификата описано в [certs/README.md](certs/README.md).

## Разработка с ИИ

Код и интерфейс разрабатывались с помощью Codex: постановка задачи, реализация, проверка на реальных данных и уточнение требований. GigaChat выполняет анализ внутри продукта.

Проверки на датасетах помогли обнаружить и исправить отказ считать объекты по группам, ошибки в базе процентного сравнения и выводы по сокращённому графику вместо всей выборки.
