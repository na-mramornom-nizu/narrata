# Narrata

**Узнайте, о чём говорят ваши данные.**

Загрузите CSV, Excel или текстовый отчёт — получите главный вывод, интерактивные графики и чат по содержимому источника. Без регистрации.

[Открыть сервис](https://narrata-nine.vercel.app/) · [Сценарий видеодемо](docs/VIDEO-PITCH.md)

## Возможности

- **Файл или текст:** drag-and-drop, выбор CSV / XLSX / XLS, вставка отчёта.
- **AI-нарратив:** короткий вывод и 2–3 предложения с контекстом данных.
- **Графики:** модель выбирает подходящие представления; табличные значения рассчитываются кодом по загруженным строкам.
- **Чат:** сравнения, фильтры, группировки, доли и другие вычисления по источнику. Поле вопроса расположено сразу под нарративом.
- **PDF:** выводы, графики и история переписки в одном документе. Экспорт доступен после завершения анализа.
- **Интерфейс:** прелоадер, понятные ошибки и повтор анализа; адаптивная вёрстка и возврат к началу результатов.

Если запрошенных сведений нет в источнике, ответ: **«В этом отчете нет такой информации»**. Ошибка сервиса обрабатывается отдельно.

## Быстрый старт

Нужны **Node.js 22+**, npm и ключ авторизации **GigaChat**.

```bash
git clone https://github.com/na-mramornom-nizu/narrata.git
cd narrata
npm ci
cp .env.example .env.local
```

Для PowerShell: `Copy-Item .env.example .env.local`.

Заполните `.env.local`:

```dotenv
GIGACHAT_AUTH_KEY=ваш_ключ_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
```

Ключ используется только на сервере. `.env.local` исключён из Git; не добавляйте ключ в переменные с префиксом `NEXT_PUBLIC_`.

```bash
npm run dev
```

Откройте [localhost:3000](http://localhost:3000). Для другого порта: `npm run dev -- --port 3001`.

Без ключа интерфейс запускается, но AI-анализ недоступен.

### Попробовать без файла

Откройте вкладку **«Вставить текст»** и вставьте учебный пример:

```text
Недельный отчёт команды разработки проекта «Аврора».
Из 50 задач 20 находятся на ревью, 10 в работе и 20 завершены.
На ревью приходится 40% задач.
В понедельник завершили 4 задачи, во вторник 6, в среду 10.
```

После анализа спросите: «Сколько задач находятся на ревью?» или «В какой день завершили больше всего задач?». Вопрос «Какой бюджет проекта?» проверяет ответ об отсутствии сведений.

## Стек и архитектура

| Задача | Инструменты |
| --- | --- |
| Приложение и API | Next.js 15, React 18, TypeScript |
| Интерфейс | Tailwind CSS, Framer Motion, Lucide |
| Графики | Recharts |
| Чтение таблиц | PapaParse, SheetJS |
| Языковая модель | GigaChat |
| Вычисления | TypeScript, SQLite через sql.js |
| PDF | pdfmake |
| Хостинг | Vercel |

**Модель интерпретирует запрос и пишет текст; вычислительный код считает значения.**

1. Браузер разбирает файл, проверяет формат и размер, формирует набор данных.
2. `POST /api/analyze` принимает Dataset и подготавливает факты и варианты визуализаций. Модель выбирает графики и формулирует нарратив; затем выполняются редактирование контекста и проверки ответа.
3. `POST /api/chat` получает `{ dataset, messages }`. Для таблиц модель предлагает операции или SQL; после валидации код выполняет расчёт. Для текста используются исходные фрагменты и подтверждающие цитаты.
4. SQL выполняется в памяти изолированного worker: только чтение, с ограничениями времени, памяти и выдачи. Постоянная база данных не нужна.
5. PDF собирается в браузере из текущего отчёта и переписки.

Это две serverless-функции Next.js. Отдельного backend-сервиса, пользовательской авторизации и векторной базы нет.

### Навигация по коду

```text
app/page.tsx              Состояния и основной экран
app/api/                  Анализ и чат
components/               Загрузка, нарратив, графики, чат, прелоадер

lib/analysis-plan.ts      Факты и варианты графиков для таблиц
lib/text-analysis.ts      Проверка анализа свободного текста

lib/*query.ts             Планы запросов и вычисления
lib/comparison.ts         Направление сравнений и процентная база
lib/download-report.ts    Экспорт PDF
tests/                    Автоматические и live-проверки
```

## Проверки

```bash
npm test                 # Автотесты без запросов к модели
npm run typecheck        # TypeScript
npm run build            # Production-сборка
npm start                # Запуск собранного приложения
```

Тесты покрывают разбор данных, вычисления, процентные сравнения, ограничения SQL, проверку текстовых фактов, контекст и PDF.

### Проверки с реальной моделью

Требуют запущенного приложения с настроенным ключом и расходуют токены GigaChat. Пользовательские датасеты не входят в репозиторий.

```bash
node --require ./tests/register.cjs tests/countries.live.cjs /path/to/countries.csv http://localhost:3001
```

Дополнительные сценарии: `tests/comparisons.live.cjs` и `tests/mvp.live.cjs`. Они рассчитаны на наборы из разработки; перед запуском проверьте пути к файлам внутри сценариев. Запускайте live-проверки последовательно.

[Подробный аудит MVP](docs/MVP-VALIDATION.md) содержит результаты конкретного прогона, а не гарантию для любой формулировки или файла.

## Ограничения и данные

- CSV: UTF-8, Windows-1251 и Windows-1252. Для Excel читается **первый лист**.
- Файл — до **20 МБ**; сериализованный запрос вместе с данными и чатом — до **4 000 000 байт**. Большая таблица может превысить лимит запроса, даже если файл прошёл проверку размера.
- Вставленный текст — до **50 000 символов**; табличный ответ чата — до **100 строк**.
- Расчёты выполняются по загруженным строкам. Контекст для модели содержит схему, статистику и ограниченные примеры; для редких сущностей может понадобиться точное название или код.
- Обычно создаются 2–3 графика. Если данных недостаточно, их может быть меньше.
- Числовые и семантические проверки снижают риск ошибок, но модель может неверно понять вопрос. Проект не гарантирует выполнение любой произвольной операции.
- Приложение не сохраняет отчёты между перезагрузками. Данные передаются серверным функциям, а контекст для анализа — GigaChat; обработка не является полностью локальной.
- В публичном MVP нет пользовательских квот, биллинга и совместной работы.

## Деплой на Vercel

1. Импортируйте репозиторий как проект Next.js.
2. Добавьте `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE` и `GIGACHAT_MODEL` в Environment Variables для нужного окружения.
3. Выполните деплой. После изменения переменных окружения нужен новый деплой.

В текущем проекте production связан с веткой `main`.

`next.config.js` включает SQL-runtime и CA-сертификат в serverless-сборку. Проверка TLS включена; происхождение сертификата описано в [certs/README.md](certs/README.md). SheetJS устанавливается из источника, указанного в `package.json`; используйте `npm ci` для воспроизводимой установки из lock-файла.

## Работа с ИИ

Код и интерфейс разрабатывались итерациями с Codex: требование → реализация → проверка на данных → уточнение → повторная проверка. В самом продукте анализ выполняет GigaChat.

[Сценарий питча](docs/VIDEO-PITCH.md) содержит реальные промпты из разработки и примеры исправлений: отказ считать группы, неверная база процентного сравнения и потеря темы источника в нарративе.
